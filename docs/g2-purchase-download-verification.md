## 실행 범위와 결과

## 브라우저 대기와 안전한 재진입

최초 준비 주문 `a03d1199-fcc2-4eae-acac-6e372b81aabc`은 브라우저 사용 설정을 기다리는 동안 최초 생성 + 30분에 만료됐다. Order·Payment가 모두 EXPIRED이고 승인 접수는 없었다. 재개 직전 기존 paymentId의 실제 PG GET은 404였다.

기존 기한이나 서버 시각을 바꾸지 않았다. 같은 상품의 현재 공개 버전·9,000원 조건으로 새 requestId의 주문을 만들고 Gateway 세션으로 이어갔다. 새 주문은 2026-10-30 10:43:26 KST 생성, 고정 기한 11:13:26 KST다. 구매 완료 뒤에도 최초 주문·결제는 EXPIRED, 원래 기한과 금융 결과 없음이 유지됐다. 새 구매의 건수 검사는 만료된 준비 주문을 삭제하는 대신 해당 주문·상품·구매 근거에 한정했다.

브라우저 설정 변경 후 실제 인증 창과 완료 화면을 확인했다. 검증 화면에 결제·라이브러리·ZIP 다운로드 완료가 표시됐고, 그 결과와 별도로 서버 DB·PG·실제 파일을 대조했다.

## 검증 도구 보정과 코드 경계

두 오류는 제품 코드의 실패와 구분한다.

1. 최초 비로그인 대조용 클라이언트가 저장한 구매자 쿠키를 재사용했다. 독립적인 빈 쿠키 저장소로 바꾼 뒤 실제 401을 확인했다.
2. 다운로드 ticket의 정상 RFC 3339 만료 시각에 나노초 소수부가 있었다. OCI Python의 시각 파서가 이를 거절해 검증 도구가 멈췄다. 비교용 소수부만 마이크로초로 정규화하고, 이미 PAID인 원래 거래의 조회·다운로드 검증을 재개했다. 추가 승인·환불로 복구하지 않았다.

이번 실행에서 운영 코드·API·스키마·업무 정책은 수정하지 않았다. 일곱 앱의 bootJar 빌드가 성공했고, 소스 1,216개와 실제 실행 JAR의 빌드 해시를 대조했다. 앞선 [Payment 604건](g1-unadmitted-expiry-fix.md)은 해당 소스의 기존 검사 근거이며 이번 실행에서 새로 반복하거나 실제 여정 건수와 합산하지 않는다.
